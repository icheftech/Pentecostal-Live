# nginx-rtmp ingest

RTMP ingest edge for Pentecostal Live. `nginx.conf.example` is a starting
point for an nginx build that includes the nginx-rtmp-module.

## Flow

```
camera → dashboard Capture Studio → media-server capture gateway ─┐
                                                                  │ publish
encoder (hardware, optional)                                      │
   │  publish rtmp://<ingest-host>:1935/live/<ingest_key>         │
   ▼                                                              ▼
nginx-rtmp (this config, port 1935) ◄─────────────────────────────┘
   │  on_publish -> POST /v1/ingest/on-publish validates the ingest key
   │
   │  media-server pulls rtmp://<ingest-host>:1935/live/<ingest_key>
   ▼
media-server ffmpeg relay (apps/media-server, one process per stream)
   ├─► YouTube / Facebook / TikTok / Instagram (RTMP fan-out, stream copy)
   └─► HLS (/var/pentecostal-live/hls/<stream_id>/index.m3u8,
        served here on :8080/hls/ for the church website player)
```

- The per-stream `ingest_key` is generated by the API on
  `POST /v1/streams/{id}/start` (regenerated every start) and returned to the
  producer as `ingest_url` for OBS.
- The `on_publish` callback validates every publish against the API: only the
  ingest key of a currently-live stream is accepted (403 otherwise), and every
  accept/stop is audit-logged with the encoder's address.
- HLS is written by the media-server's ffmpeg process (not by nginx-rtmp),
  so the media-server and nginx must share the HLS directory
  (`PENTECOSTAL_LIVE_HLS_ROOT`, default `/var/pentecostal-live/hls` in Docker).
